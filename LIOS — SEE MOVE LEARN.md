# LIOS — SEE MOVE LEARN

**Status:** Open — no Experiment pairing yet exists (04_Experiments gap). Drafted for review.
**Position in LIA:** Layer-subsystem note — the operational cycle name (LIOS = Living Intelligence Operating [System/Sequence]) for the concrete SEE → MOVE → LEARN loop that the more abstract Bidirectional Feedback Loops mechanism runs as.

---

## 1. Problem this component solves

Bidirectional Feedback Loops describes registration → threshold → propagation in fairly abstract, architectural terms. LIOS is the note that gives that abstraction a concrete, memorable operational cycle — the thing an actual node (human, AI, or hybrid) actually does, moment to moment, that the architecture is a model of. Without this note, the framework has a rigorous internal mechanism but no simple operational vocabulary for describing what a node does day to day.

## 2. Core definition — the three-phase cycle

**SEE:** gather and scope context (this is Context Architecture's three-axis operation — temporal, relational, situational — performed live, plus Situated Intelligence's use of what's available rather than what's missing).

**MOVE:** act within current agency bounds (Agency Architecture) and current boundaries (Boundary Architecture) — this is where a node's behavior, whether newly adapted or not yet changed, actually happens.

**LEARN:** register the outcome as a candidate update (Learning Architecture §1's Registration step), which either confirms toward eventual adaptation or doesn't, per Learning Architecture §4's confirmation criterion.

The cycle is continuous, not a one-shot sequence: LEARN feeds back into the next SEE, which is exactly Bidirectional Feedback Loops' Step 1 restated at the operational-cycle level rather than the cross-layer-architecture level.

## 3. LIOS as the same mechanism at every layer — a direct test of Fractal Property

If Fractal Property's weak claim (recurring structural axes at every layer) is right, SEE-MOVE-LEARN should be describable at every layer without forcing the fit: an Individual sees/moves/learns; a Dyad, jointly, does the same (its "seeing" is Context Architecture's Dyad-layer relational scope; its "moving" is Agency Architecture's shared/negotiated agency); a Network's SEE-MOVE-LEARN is mediated through Institutional Intelligence's formalized-decision mechanism rather than direct perception. This is a genuinely testable instance of Fractal Property's §4 proposed test, using LIOS itself as the probe rather than the external tech-example mapping — worth running both tests and comparing results.

## 4. Relationship to the Living Blueprint Implementation Roadmap

The six-phase roadmap (Build Trust → ... → Evolve a Regenerative Ecosystem) can be read as successive rounds of SEE-MOVE-LEARN operating at progressively outward layers, with each phase representing the point where a given layer's cycle becomes reliable enough to support the next layer's cycle depending on it. This gives the roadmap a second mechanical grounding, alongside the loop-cadence reading already established in Bidirectional Feedback Loops §3 — the two readings (cadence-based, cycle-reliability-based) should be checked for consistency rather than assumed to be two independent confirmations of the same six phases.

## 5. Open questions

- Does LEARN in the LIOS cycle map cleanly onto Learning Architecture's Registration step, or is there a missing bridge — does LIOS's LEARN also need to include Adaptation Architecture's threshold-crossing (Step 2), or is that deliberately excluded from a single cycle iteration and left for a later one?
- Is "LIOS" meant as a formal operating-system metaphor (implying something more totalizing — a full runtime, not just a cycle) or a lighter mnemonic for the three-phase loop? The name suggests more weight than this draft has given it — flag for clarification before treating this note as complete.
