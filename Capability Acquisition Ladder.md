A capability does not need to be purchased or built in order to become part of an intelligence system.

The Capability Acquisition Ladder defines progressively more committed ways of obtaining access to a capability, beginning with resources that already exist and ending with building the capability ourselves.

Start with the lowest-cost, most reversible path that can generate sufficient learning and capability. Escalate only when evidence justifies greater commitment.

| 1   | Borrow                | Very Low    | Yes     | Gain temporary hands-on experience                 |

| 13  | Build / Develop       | Very High   | No      | Create the capability internally                   |

  

Four Acquisition Modes

The ladder can be understood as four broader modes:

1. Access

- Existing resources
- Borrow
- Institutional access
- Rental
- Lease

Question:

Can we use the capability without owning it?

2. Relationship

- Partnership
- Manufacturer pilot
- Sponsorship
- Stipend / Fellowship
- Grant

Question:

Can another actor help us obtain the capability while creating mutual value?

3. Ownership

- Used / Refurbished
- Purchase

Question:

Has the capability become sufficiently valuable to justify ownership?

4. Creation

- Shared Infrastructure
- Build / Develop

Question:

Does the capability need to be created or controlled by the system itself?

  

Acquisition Decision Gate

Before escalating to a more expensive or less reversible acquisition path, evaluate seven dimensions.

1. Capability Gap

What exactly is missing?

- Experience
- Capture
- Context
- Sensemaking
- Learning
- Adaptation
- Action
- Measurement
- Infrastructure

2. Minimum Required Access

What is the minimum level of access necessary?

- Observe
- Experiment
- Use
- Operate
- Integrate
- Modify
- Own
- Build

3. Duration

How long is the capability required?

- One-time
- Short-term
- Repeated
- Long-term
- Permanent

4. Learning Requirement

Are we trying to obtain the capability, or are we first trying to learn whether the capability is needed?

If uncertainty is high, favor reversible approaches:

Existing → Borrow → Institutional Access → Partnership → Pilot → Rental

Only escalate after evidence is accumulated.

5. Strategic Control

How much control is actually required?

Low control

→ Access / Borrow / Partnership

Moderate control

→ Rental / Lease

High control

→ Purchase / Ownership

Very high control

→ Shared Infrastructure / Build

6. Persistence

Does the capability need to remain continuously available?

If No, favor temporary access.

If Yes, evaluate:

Lease → Ownership → Shared Infrastructure → Build

7. Intelligence Value

What will acquiring this capability teach us?

The acquisition should ideally generate:

Experience → Evidence → Context → Knowledge → Capability → Adaptation

  

The Reversibility Principle

Acquisition can be viewed as a reversibility gradient:

Existing

   ↓

Borrow

   ↓

Institutional Access

   ↓

Partnership

   ↓

Pilot

   ↓

Rental

   ↓

Lease

   ↓

Ownership

   ↓

Shared Infrastructure

   ↓

Build / Develop

As the system moves downward, commitment generally increases while reversibility decreases.

Therefore:

Maximize learning before maximizing commitment.

This is not simply a financial optimization principle.

It is an intelligence optimization principle.

The system should learn enough about a capability before making an irreversible commitment to it.

The Acquisition Rule

Use the least committed acquisition path that can produce enough evidence to make the next decision intelligently.

This produces a progression:

Access → Experiment → Learn → Validate → Commit → Integrate → Adapt

rather than:

Identify → Purchase → Hope

Key Principle

The system should not ask first:

“Can we afford to buy this?”

It should ask:

“What is the minimum commitment required to learn whether we need this capability?”

Only after that question is answered should the system consider ownership, infrastructure, or development.

The Capability Acquisition Ladder is a decision framework for obtaining capabilities through progressively greater commitment, using learning and evidence to determine when the system should move from access to ownership or creation.
